# Privacy Policy

Remote App is designed for private remote-computing workflows. There are no
ads, third-party trackers, behavioral profiles, or mandatory telemetry.

## Defaults

Telemetry and crash reporting are **off by default**. Installing, updating,
changing release channels, or joining the beta does not enable either option.
Feedback is never submitted in the background.

## Feedback

The feedback preview always contains application version, selected channel,
operating system, CPU architecture, kernel version, and X11/Wayland status.
These fields are visible before submission. Users separately choose whether to
include up to 200 conservatively redacted log lines, the last 30 content-free
action categories, or a screenshot path.

Remote App intentionally excludes session and terminal content, credentials,
hostnames, usernames, clipboard data, command text, and file contents. Because
redaction cannot understand every future log message, users must inspect and
may edit `preview.md` before sending it.

The default backend is the public GitHub Issues API. Public submissions are
governed by GitHub's privacy terms. Email is available as a no-API fallback.

## Crash Reports

When explicitly enabled, the Sentry integration sends a normalized panic,
symbolicated backtrace, app version, release channel, OS, and architecture to a
self-hosted Sentry instance. Default PII, request data, user data, error text,
extras, and breadcrumbs are removed before sending. Hard-crash minidumps may
be generated by the companion `minidumper` monitor and uploaded only while the
same opt-in is active; the receiver symbolicates them using project debug
files and `symbolic`.

Minidumps can contain process memory, including session or file content. They
therefore require separate per-dump consent after a clear warning and are retained
for the shortest operational period. They are never attached to public issues.

## Anonymous Metrics

If explicitly enabled, Remote App sends only:

- Aggregate app launch count.
- Counts of broad feature categories used.
- Allow-listed performance durations in milliseconds.
- App version, channel, OS, and CPU architecture.

There is no installation identifier, IP field, hostname, session identifier,
or content field in the telemetry schema. The receiver is a project-operated
Matomo or Plausible gateway configured with IP anonymization and short
retention. Network infrastructure may temporarily process an IP address to
deliver the request; the application does not place it in the payload.

Run `remote-app --show-telemetry` or
`remote-app-headless --show-telemetry` to print exactly what would be sent,
without sending it. Disabling telemetry stops future collection and delivery.

Channel checks fetch only `stable`, `beta`, or `nightly` manifests from the
deployment-configured `MBXT_UPDATE_BASE_URL`. Every manifest is verified with
the Ed25519 key in `MBXT_UPDATE_PUBLIC_KEY`; artifacts must match the signed
SHA-256 digest before a package manager or user installs them. Update checks do
not enable telemetry.

## Control and Contact

Settings expose independent telemetry and crash-reporting controls. Users can
submit privacy questions in Discussions and private security concerns through
the process in `SECURITY.md`. Maintainers document material policy or schema
changes in the changelog before release.
