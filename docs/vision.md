# Vision

Remote App aims to become the trusted, open standard for remote computing on
Linux: one native tool for terminals, files, tunnels, graphical applications,
devices, and cloud-native environments without sacrificing user control.

## Principles

- **Local first:** sessions, credentials, terminal content, and files remain on
  the user's machine unless the user explicitly connects or shares them.
- **Secure by default:** clear trust boundaries, encrypted secrets, signed
  updates, least privilege, and no silent execution of imported configuration.
- **Open and interoperable:** open protocols and formats come before proprietary
  services. Components should be reusable where a stable API has real users.
- **Linux native:** X11 and Wayland, desktop portals, distributions, hardware,
  and accessibility receive focused first-party attention.
- **Fast and dependable:** terminal latency, startup, memory, network recovery,
  and long-running stability are product features.
- **No surveillance business model:** no advertising, forced analytics, user
  profiles, or cloud-content collection. Opt-in metrics remain inspectable.
- **Community governed:** demand and tradeoffs are public; votes inform but do
  not override security, maintainability, accessibility, or project capacity.

## Three-to-Five-Year Direction

Remote App should make Linux a first-class control plane for servers, clusters,
containers, and edge/IoT devices. Cloud integrations for AWS, GCP, and Azure
remain modular so no provider controls the product. Shared access, plugins, and
gateways use documented protocols that other projects can implement.

Where implementation reveals protocol ambiguity or missing security guidance,
the project should contribute tests, documentation, and proposals upstream and
participate in open standards rather than creating unnecessary private
extensions.

Sustainability comes from a larger maintainer group, individual donations,
transparent sponsorship, and optional support or hosting. Core features remain
open and usable without an account. Growth is valuable only when maintainers can
continue to review security reports, support releases, and say no to scope that
would make the application unreliable.

This is an aspiration, not a market-share promise. Success is measured by user
trust, interoperability, maintainable contributions, and reliable daily use,
not by telemetry volume or feature count.
