# Community

GitHub is the only active official platform today. Every other channel below
is explicitly marked as active or not-yet-created so newcomers are not sent to
unofficial rooms or dead accounts.

## Platforms

| Channel                                    | Purpose                             | Status                                                     |
| ------------------------------------------ | ----------------------------------- | ---------------------------------------------------------- |
| GitHub code, issues, Discussions, releases | Canonical collaboration             | Active                                                     |
| GitHub Projects roadmap board              | Public priority view                | Active                                                     |
| Matrix/Discord chat                        | Real-time user and contributor help | Not created; unlisted rooms are unofficial                 |
| Mastodon/Twitter announcements             | Release announcements               | Not created                                                |
| Reddit (r/linux, r/selfhosted, r/sysadmin) | Occasional project posts            | No standing presence; posts are ad hoc                     |
| Hacker News                                | Major releases only                 | Per-release, not a community home                          |
| YouTube tutorials and demos                | Visual guides                       | No official channel yet                                    |
| Blog and technical deep-dives              | Design and protocol notes           | No project website yet; notes live in Discussions and docs |

Do not trust rooms, accounts, or downloads not linked from this repository.

## Communication Norms

- Assume good faith and be patient with newcomers.
- No gatekeeping; beginner questions and docs fixes are contributions.
- Constructive feedback only: describe the problem, suggest a next step, and
  separate blocking issues from style preferences.
- Public by default; private only for security reports, conduct reports, and
  personal data.
- All rules apply equally to maintainers.

## Contribution Paths

Code, documentation, design, testing, translation, community support, advocacy,
and (future) funding — see `CONTRIBUTING.md`. Translation is manual via
`locales/`; no Weblate instance exists. Funding channels do not exist yet.

## Recognition

`CONTRIBUTORS.md` uses the all-contributors format and is updated manually
until the bot is installed. Release notes mention contributors with consent.
There is no active "Contributor of the Month", badge automation, or swag
program; each starts only when announced in `CONTRIBUTING.md`. GitHub's native
contributor graphs always work.

## Community Health Metrics

Maintainers track, on a best-effort quarterly basis: monthly active
contributors, first-time contributor retention, issue response time, PR merge
time, and survey sentiment. Metrics are reported in aggregate; opt-in telemetry
is never required for recognition or participation.

## Outreach and Partnerships

SEO-friendly docs, comparison articles, conference talks (for example FOSDEM or
Linux Plumbers), distro packaging, education use, and company case studies are
welcome but opportunistic given current capacity. Distribution inclusion
(Flathub, Snapcraft, AUR, PPA, COPR) requires each platform's own review and
credentials; contributor packaging help is appreciated. No partnerships,
sponsorships, or podcast appearances are currently committed.
