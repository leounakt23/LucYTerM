# RFC 0000: Short Descriptive Title

- Status: Draft
- Authors: GitHub handles
- Discussion: URL
- Tracking issue: URL or `Not assigned`
- Target: Candidate release or `Unscheduled`
- Review date: YYYY-MM-DD

## Summary

Explain the proposal and its user-visible value in a short paragraph.

## Problem

Describe affected users, current workflow, frequency, and evidence. Link public
feedback and state what is out of scope.

## Goals and Non-Goals

List observable outcomes and explicit boundaries.

## Proposed Design

Describe behavior, UI/CLI/API changes, data flow, dependencies, platform
support, errors, and recovery. Include examples where useful.

## User Experience and Accessibility

Cover discoverability, keyboard-only use, assistive technology, localization,
failure messages, and safe defaults.

## Security and Privacy

Identify assets, actors, trust boundaries, permissions, credentials, user
content, network services, logging, telemetry, abuse cases, and mitigations.
Do not put undisclosed vulnerability details here.

## Compatibility and Migration

Cover configuration and persisted formats, API/protocol compatibility, import
and export, rollback, deprecation needs, and supported distributions.

## Performance and Reliability

Define expected startup, latency, memory, CPU, storage, and network impact plus
failure isolation and measurable budgets.

## Alternatives

Include doing nothing, external-tool integration, and smaller approaches. State
why the proposed tradeoff is preferable.

## Implementation Plan

Describe incremental deliverables, feature flags, dependencies, test strategy,
documentation, release criteria, and responsible owner. Experimental flags use
the `--enable-experimental-*` convention and do not silently enroll users.

## Maintenance and Sustainability

Name the long-term owner, upstream dependencies/services, recurring operations,
support burden, and exit plan if ownership or upstream support disappears.

## Experiment and Rollback Plan

Define success measures, stop conditions, maximum review date, data
export/migration, disable path, and cleanup ownership.

## Unresolved Questions

List decisions needed before acceptance.

## Decision

Maintainers complete this section with the date, rationale, dissent, and any
conditions. Community votes are evidence, not the sole decision mechanism.
