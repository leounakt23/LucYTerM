# AGENTS.md

## Repo facts

- Rust workspace (edition 2021, MSRV 1.80, toolchain pinned to 1.85.1 in `rust-toolchain.toml`). Linux-only desktop app: Iced 0.13 + wgpu GUI (`remote-app`) plus headless CLI (`remote-app-headless`, `src/bin/cli.rs`).
- Linux system deps required to build: `pkg-config`, `libudev-dev`, `libdbus-1-dev` (see CI in `.github/workflows/ci.yml`).
- `.cargo/config.toml` sets `jobs = 2` on purpose — local builds are slow by design. It also defines the `cargo xtask` alias.
- `fuzz/` is excluded from the workspace (own crate, cargo-fuzz + nightly).

## Commands

```sh
cargo fetch --locked
cargo check --workspace --all-targets --all-features
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings   # CI gate
cargo test --workspace
```

- CI runs everything `--locked --all-features`; lint also runs `cargo doc --workspace --all-features --no-deps` and `mdbook build docs`, so keep both clean.
- `cargo xtask docs|i18n|release`: `docs` = mdBook build, `i18n` = validates `locales/en-US/app.ftl` (all user-facing strings are Fluent keys), `release` = `packaging/scripts/build-all.sh`.
- Pre-commit (`.pre-commit-config.yaml`): fmt + clippy + test on commit; `cargo audit` runs at pre-push only (DB download is slow).

## Build script (`build.rs`) coupling

- Shell completions are generated by `build.rs` via `clap_complete` from the shared CLI definition in `crates/cli` (`mbxt-cli`) — both binaries use that definition; edit CLI args there, not in the binaries.
- `build.rs` asserts `crates/terminal/shaders/terminal.wgsl` exists and contains `vs_main`/`fs_main`/`atlas_texture`; the shader is `include_str!`-embedded.

## Architecture boundaries

- Layer crates: `crates/core` (domain types, no I/O deps) → `terminal` (vte/grid/wgpu) / `connections` (transports, feature-gated) / `storage` (SQLite+AES-GCM, RON config) / `system` (keyring, clipboard, signals) → `cli` → root `remote-app` crate (`src/app` is the composition root, Elm/MVU style).
- The UI (`src/ui`) must not depend directly on russh, filesystem protocols, or platform handles; async I/O stays off the UI thread via session actors and bounded channels.
- Protocol support is feature-gated: `ssh` (implies `sftp`), `telnet`, `serial`, `rdp`, `vnc`, `x11`, `gssapi`. Default is `ssh,telnet`. Changes must keep `--no-default-features` and per-gate builds compiling (feature-matrix gate).

## Testing

- Live integration tests are `#[ignore]`d and opt-in; they never connect to arbitrary hosts. Env gates: `MBXT_SSH_TEST_*`, `MBXT_SFTP_TEST_*`, `MBXT_FORWARD_TEST_*`, `MBXT_X11_TEST_*`, `MBXT_VNC_TEST_*` (addr/user/password).
- Run a live suite against the disposable Docker services:
  ```sh
  docker compose -f docker/compose.e2e.yml up -d --wait
  cargo test --all-features --test sftp_integration -- --ignored --nocapture
  docker compose -f docker/compose.e2e.yml down --volumes
  ```
  (`tests/`: `ssh_loopback`, `sftp_integration`, `forward_integration`, `x11_integration`, `telnet_live`, `vnc_integration`, plus non-live `config_integration`, `network_tools`, `properties`, `snapshots`.)
- Snapshots use `insta`: review with `cargo insta review`; only update snapshots when the change is intentional.
- Fuzz targets in `fuzz/fuzz_targets/` (parsers: config, macro, ping, subnet, vte). Fuzz input must not be printed — it may contain credentials/control sequences.
- Benchmarks: `cargo bench --bench performance` (Criterion, `benches/performance`).

## Conventions

- Conventional Commits: `feat:`, `fix:`, `docs:`, `perf:`, `security:`, `build:`, `test:`, `chore:`; keep commits buildable.
- No `unwrap`/`expect` on untrusted input or I/O paths; typed errors via `thiserror`/`anyhow`. `unsafe` needs a safety comment and platform isolation.
- Secrets never appear in logs, fixtures, screenshots, or commit messages.
- Behavior changes ship tests + docs in the same PR.
